# 데이터 보관 정책 제안 (#105)

이 문서는 **제안**이다. 출석·입장 데이터에 보관 기간이나 삭제 규칙을 새로 정하지 않았고, 아래 "열린 질문"은 운영·기획이 정해야 한다.
지금 코드는 박람회를 삭제할 때(`DELETE /internal/expos/{expoId}`)만 데이터를 지운다.

## 지금 구현된 것

| 테이블 | 동작 | 이유 |
| --- | --- | --- |
| `tb_cancellation_aborted` | `CANCELLATION_ABORTED_RETENTION_DAYS`(기본 0 = 끔)가 양수이면 그 일수보다 오래된 행을 1시간마다 지운다 | 중단된 취소 작업의 operationId 기록일 뿐 비즈니스 기록이 아니다. 중단 뒤 늦게 도착한 같은 operationId의 acquire를 막는 용도라 일정 기간이 지나면 의미가 없다. 신청 서비스의 재시도·지연 한도보다 충분히 길게(예: 30일 이상) 둔다 |

여러 인스턴스가 있어도 어드바이저리 락으로 한 곳만 돈다.

## 지금처럼 둔다 (기간으로 지우지 않음)

| 테이블 | 담고 있는 것 | 지금 방침 |
| --- | --- | --- |
| `tb_qr_entry`, `tb_qr_token` | 종이 QR 발급·입장 기록 | 입장 기록은 운영이 사후 확인하는 근거다. 박람회 삭제 때만 지운다 |
| `tb_standard_program_attendance`, `tb_training_program_attendance` | 프로그램 출석 | 출석 증빙이다. 박람회·프로그램 삭제 때만 지운다 |
| `tb_preregister_session` | 사전등록 회차와 취소 revision | 오래된 PUT·DELETE를 무시하는 기준(revision)이라 임의로 지우면 되돌림이 생길 수 있다 |
| `tb_cancellation_guard` | 취소 진행·확정 보호 | 시간으로 자동 해제하지 않는 것이 설계다(신청 서비스의 commit/abort로만 바뀐다) |
| `tb_deleted_expo`, `tb_deleted_program` | 삭제된 박람회·프로그램 표식(재생성 방지) | 지우면 삭제된 박람회에 다시 기록이 쌓일 수 있다 |

## 열린 질문 (결정 필요)

1. 박람회 종료 후 출석·입장 데이터를 얼마나 보관하는가(예: 종료 N개월). 개인정보 보관 기간 방침과 맞춰야 한다. **결정 주체: 운영·기획 + 개인정보 담당.**
2. 기간이 지난 뒤 삭제할지, 익명화(토큰·참가자 ID 제거)나 집계만 남길지. 박람회 서비스가 종료일을 알고 있으므로 정리 기준일을 어디서 가져올지(이 서비스가 박람회 서비스를 호출할지, 박람회 서비스가 정리를 요청할지) 함께 정해야 한다.
3. 삭제 전에 백업·내보내기가 필요한지, 필요하면 누가 어떤 형식으로 받는지.
4. `tb_deleted_expo`·`tb_deleted_program` 표식을 언제까지 두는지. 박람회 서비스가 같은 ID를 다시 쓰지 않는다는 보장이 있으면 정리할 수 있다.
5. `tb_preregister_session`의 취소 기록을 박람회 종료 후에도 남길 이유가 있는지(사후 분쟁 확인 등).

결정이 나면 이 문서를 갱신하고, 규칙마다 설정으로 끌 수 있고 기본은 꺼진 채로 별도 이슈·PR에서 구현한다.
